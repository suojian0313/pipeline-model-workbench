# 轻量化模型平台试题：官方技术资料核对

核对日期：2026-10-22。本文只核对技术能力与选型依据；实际数据字段、构件关联和模型性能须以试题附件检查与运行结果为准。

## 1. 先理解三个不同的概念

`tileset.json` 是瓦片数据集的入口；`.b3dm` 是其中一种瓦片内容格式；CesiumJS 是读取和显示这些内容的引擎。Vue3 继续负责树、表单、属性面板等界面，不会被三维引擎替代。

**官方事实：** b3dm 把批量模型的几何、材质与逐构件属性组织在一起，内部包含二进制 glTF；Batch Table 可以提供逐模型属性，`batchId` 将几何归属到某个 feature。b3dm 已在 3D Tiles 1.1 中被标为 deprecated。[3D Tiles：Batched 3D Model 规范](https://raw.githubusercontent.com/CesiumGS/3d-tiles/main/specification/TileFormats/Batched3DModel/README.adoc)

**本题推断：** 题目既然指定现成 b3dm，就先消费既有格式。deprecated 不代表现在不能加载，更不构成必须先转换所有附件的理由。关键问题是其 feature 属性是否包含能与 structure、EP3D、焊接表关联的稳定标识；不能把瓦片内部的局部 batchId 直接假定成全局业务 ID。

## 2. CesiumJS 可以读取自己托管的模型

**官方事实：** `Cesium3DTileset.fromUrl(url)` 接收 tileset JSON URL，官方示例使用 `http://localhost:8002/.../tileset.json`；当前文档也仍明确列出 B3DM 内容。[Cesium3DTileset API](https://cesium.com/learn/cesiumjs/ref-doc/Cesium3DTileset.html)

**本题推断：** 可以通过开发服务器或 Nginx/对象存储暴露附件目录，再加载入口 URL；此路径不要求先上传 Cesium ion。应保留入口文件与内部 URI 的相对目录关系，跨域部署时正确配置 CORS。浏览器应通过 HTTP(S) 访问模型资源，不能把硬盘路径直接当普通网页资源 URL。

## 3. 拾取、高亮、属性展示有现成能力，但状态要自己管理

**官方事实：** `Scene.pick` 或 content 的 `getFeature` 可以取得 feature；`getProperty`/`getPropertyIds` 读取属性，`color` 控制染色，`show` 控制显隐。颜色会与原色相乘。feature 修改只在瓦片内容存活期间有效，卸载后需保存，在 `tileVisible` 时重新应用。[Cesium3DTileFeature API](https://cesium.com/learn/cesiumjs/ref-doc/Cesium3DTileFeature.html)

**本题推断：** 用统一的 `selectedComponentId` 驱动树节点与三维选择；用 `componentId → 业务状态` 保存已焊接、选中等信息。加载/显示瓦片时将业务状态映射成样式；瓦片卸载时清理失效的 feature 引用。颜色优先级需明确，例如“选中颜色 > 已焊接颜色 > 原始外观”，避免取消选择后错误恢复原色。

**本题推断：** 树节点点击定位，还需要可用的构件位置或包围体。不能仅凭能拿到 feature 就保证可精确飞到单个构件。若附件不提供 bounds，需要补建 `componentId → bounds` 索引，并正确处理模型局部坐标到场景坐标的变换。

## 4. 15 秒和 20 FPS 不是设置一个参数就能保证

**官方事实：** `maximumScreenSpaceError` 控制 LOD 细化，数值越大通常越省资源、细节越少；`cacheBytes` 和 `maximumCacheOverflowBytes` 控制瓦片缓存预算；`initialTilesLoaded` 表示初始视图所需瓦片完成加载，`loadProgress` 提供请求/处理数量。[Cesium3DTileset API](https://cesium.com/learn/cesiumjs/ref-doc/Cesium3DTileset.html)

**官方事实：** `requestRenderMode` 让场景按需渲染；外部代码改变场景后，某些情况需要主动 `scene.requestRender()`。[Scene API](https://cesium.com/learn/cesiumjs/ref-doc/Scene.html)

**本题推断：** 必须明确“15 秒”的计时起点及模型可见判定；分别记录首个有效画面和初始视图加载完成。20 FPS 应在持续旋转/缩放的真实交互期间测量，单帧预算约 50ms；按需渲染的静止画面没有必要持续达到 20 FPS。需要测网络、瓦片大小、GPU 内存、draw calls、分辨率和业务主线程耗时。若数据没有有效分层，单纯调整 LOD 参数也不会凭空产生简化模型。

## 5. Three.js 路线需要额外的 3D Tiles 支持

**官方事实：** NASA-AMMOS 的 `3d-tiles-renderer` 专门实现 3D Tiles 加载/渲染，支持 Three.js 和 Babylon.js，并声明有部分规范能力尚未实现。[3DTilesRendererJS 官方仓库](https://github.com/NASA-AMMOS/3DTilesRendererJS)

**本题推断：** 若选择 Three.js，需要搭配该类瓦片渲染器或自行实现加载调度、缓存和格式处理；不能将 b3dm 直接当作 GLB 交给普通 GLTFLoader。对“Vue 熟练、Node 尚在成长、首次接触 3D Tiles”的情况，CesiumJS 通常更容易先覆盖本题需求。这是结合题目格式的工程判断，不是任何性能排名。

## 6. 后端与云 SQL：先做模块化单体

**官方事实：** NestJS 不绑定数据库，可通过 Node 驱动接入 SQL/NoSQL，也可采用 ORM/查询构建器；官方文档覆盖 TypeORM、Drizzle、Prisma 等集成。[NestJS 数据库文档](https://docs.nestjs.com/techniques/database)

**当前实现：** 前端建议仍为 `Vue3 + TypeScript + Vite + CesiumJS`；本项目已实现 `Node.js + Fastify + TypeScript + pg` 与 `Python + FastAPI + 同步 psycopg 3` 两套独立后端，共用 PostgreSQL。Node 版直接用 pg 执行参数化 SQL，Python 版采用普通 `def` 路由在线程池执行同步数据库访问。每套后端各用一个服务进程，按配置、模型索引、路由和导入 CLI 分文件。NestJS 是后续可选拓展，当前没有使用；也未引入 ORM、微服务、消息队列、Redis 或 Kubernetes。

**本题推断：** Excel 导入要做稳定 ID 关联、日期规范化、重复行处理和事务写入。焊缝与两侧构件的关系应显式落表，不能只根据空间“看起来相邻”猜测。点击刷新重新 GET 云数据库状态即可满足通常意义的刷新同步；若题目进一步要求多浏览器即时推送，再评估 SSE/WebSocket。

## 7. 云数据库连接秘密留在服务端

**官方事实：** Vite 的 `VITE_*` 环境变量会进入客户端产物，官方明确要求不要在其中放敏感密钥，并建议用后端/函数保护秘密。[Vite 环境变量文档](https://vite.dev/guide/env-and-mode)

**本题推断：** 普通云 SQL 的连接串、账号密码由 Node 后端读取环境变量。浏览器请求业务 API，由后端校验和执行参数化查询；把密码写进 `.env` 并加 `VITE_` 前缀仍会泄露。

## 阅读与验证顺序

先读 b3dm 规范的 Overview、Batch Table，再读 Cesium3DTileset 的 fromUrl、LOD 与事件，然后读 Cesium3DTileFeature 的拾取与生命周期说明。随后用一个最小实验回答四个问题：模型是否能加载、能否取得唯一业务 ID、树/属性/焊接记录能否关联、树节点能否获得定位 bounds。确认这些之后，再设计完整界面和导入 API。

## 8. Python 第二版本：用相同业务学习不同语言

**当前实现：** 已交付两个可独立运行的后端：`Node.js + Fastify + TypeScript + pg`、`Python + FastAPI + 同步 psycopg 3`，共用 PostgreSQL 表结构、业务规则与 HTTP API 契约。前端可通过 API 地址切换。Node 使用连接池，Python 使用普通 `def` 路由和每次请求获取的同步连接；两版都直接访问 PostgreSQL。当前先练习参数化 SQL、事务和连接生命周期，ORM 与 NestJS 留作可选拓展。

### 8.1 FastAPI 的 async def 与普通 def

**官方事实：** FastAPI 调用的普通 `def` 路由、依赖会在线程池运行；`async def` 适合调用可 await 的异步库。自己在异步路由中直接调用的普通辅助函数，不会因使用 FastAPI 就自动转移到线程池。[FastAPI 并发文档](https://fastapi.tiangolo.com/async/)

**当前实现与进阶知识：** 当前 Python 数据库路由使用普通 `def + 同步 psycopg`，由 FastAPI 在线程池中执行；Excel 解析是单独的预处理 CLI，不在 HTTP 请求中运行。以后若改为异步数据库访问，可采用 `async def + AsyncConnection`。阻塞解析需要明确安排线程卸载或采用适当的同步入口；不能只把函数名改成 `async def` 就认为解析不会阻塞。CPU 密集任务也不会因加 await 自动获得并行计算能力。

### 8.2 Pydantic 校验发生在运行时

**官方事实：** 用 Pydantic `BaseModel` 声明请求模型后，FastAPI 会解析 JSON、按模型转换类型并验证数据，同时生成 JSON Schema/OpenAPI 文档。[FastAPI 请求体文档](https://fastapi.tiangolo.com/tutorial/body/)

**本题推断：** 焊接状态更新和 Excel 导入都应有明确字段校验。Python 类型注解不能一概等同于 TypeScript interface，也不是所有带注解的普通函数都会自动校验。`value: str | None` 表示可为 None；要允许请求缺省，通常还需默认值 `= None`。本项目的 welded_on 必须显式提供，可传 null，但不能缺省。当前 Node 错误体为 `{error}`，FastAPI 为 `{detail}`；成功数据与约定状态码一致，前端可统一适配错误结构。

### 8.3 psycopg 3 的占位符与异步进阶知识

**官方事实：** psycopg 3 提供 `AsyncConnection`/`AsyncCursor`；连接需要 await，`cursor()` 本身不需要 await，执行与取结果需要 await。同一连接上的查询仍然串行，并共享会话/事务；并发请求应管理连接池。[psycopg 并发文档](https://www.psycopg.org/psycopg3/docs/advanced/async.html)

**官方事实：** 参数绑定写成 `execute("... WHERE id = %s", (component_id,))`；`%s` 不加引号，参数另传，不使用字符串 `%`/拼接替换。单元素元组要带逗号。官方示例直接绑定 `datetime.date` 到日期字段。[psycopg 参数绑定文档](https://www.psycopg.org/psycopg3/docs/basic/params.html)

**本题推断：** Node `pg` 的 `$1` 与 psycopg 的 `%s` 是驱动接口的差异，业务 SQL 逻辑可以相同，驱动代码不能逐字照搬。焊接日期若只表示日历日期，API 统一 `YYYY-MM-DD`，Python 使用 `date`，数据库使用 `DATE`；不要绕成带时区时间再截取日期。

**当前实现与 Windows 进阶知识：** 本项目已用 uv 创建 `backend-python/.venv` 并安装锁定依赖，数据库访问采用同步 psycopg，没有使用 AsyncConnection。psycopg 文档提示其异步接口不兼容 Windows 默认 ProactorEventLoop；以后改为异步驱动时，再核对 ASGI 服务器使用的事件循环。[psycopg 并发文档](https://www.psycopg.org/psycopg3/docs/advanced/async.html)

### 8.4 Python coroutine 不是直接照搬 JavaScript Promise

**官方事实：** Python 调用 `async def` 只创建 coroutine 对象，不会自动调度执行；通常通过 await、`asyncio.create_task` 或入口的 `asyncio.run` 执行它。[Python asyncio：coroutines and tasks](https://docs.python.org/3/library/asyncio-task.html)

**对照解释：** JavaScript 的 async 函数在调用时已开始执行函数体，返回 Promise；Python 的上述行为不同。理解此区别后再学习并发调度，避免写出只创建 coroutine 却从未执行的代码。[ECMAScript：AsyncFunctionStart](https://tc39.es/ecma262/multipage/control-abstraction-objects.html#sec-async-functions-abstract-operations-asyncfunctionstart)

**进阶知识：** 若以后编写 `async def` 路由，可在服务器管理的事件循环内使用 await；`asyncio.run` 留给独立脚本入口，而非放进每个异步接口。异步连接资源可用 `async with` 管理，它承担确定的进入/退出清理职责，不是 JavaScript 普通代码块的同义写法。当前同步数据库路由使用普通 `with` 关闭连接并在异常时回滚，不使用上述异步连接写法。

### 8.5 当前使用 uv 与 lock 重建项目环境

**官方事实：** `venv` 为项目创建独立包环境，常用目录名 `.venv`；官方指出该目录不应提交 Git，也不应作为可复制/迁移的交付物。[Python venv 文档](https://docs.python.org/3/library/venv.html)

**官方事实：** uv 以 `pyproject.toml` 声明项目和依赖，使用 `uv.lock` 记录解析结果，默认在项目旁创建 `.venv`；`uv sync` 同步环境，`uv run` 在项目环境内执行命令。使用 `--locked` 时，锁文件过期会报错，不会自动更新它。[uv 项目结构](https://docs.astral.sh/uv/concepts/projects/layout/)、[uv 锁定与同步](https://docs.astral.sh/uv/concepts/projects/sync/)

**当前实现：** `backend-python/pyproject.toml`、`backend-python/uv.lock` 和本机 `.venv` 均已创建。在项目根目录运行 `uv sync --project backend-python --locked` 可按现有锁文件重建环境；运行脚本用 `uv run --project backend-python --locked python ...`。不要把 Node 的 `node_modules`、Python 的 `.venv`、依赖声明和锁文件混为一件事：前两者是本机依赖目录，后两者用于重建环境。
