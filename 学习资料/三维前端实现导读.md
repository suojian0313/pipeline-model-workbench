# 从 Vue3 经验读懂三维工作台

先打开工作台操作，再按以下顺序看代码。页面、Node 与 Python 都是本项目的真实实现，可边改边观察。

## 1. Vue 管业务状态，Cesium 管渲染对象

`frontend/src/App.vue` 保存选中的业务 ID、结构树、焊接记录与完成进度。`ModelViewport.vue` 将这些简单数据传给普通 TypeScript 类 `lib/PipelineViewer.ts`。大型 Cesium 对象不进入 Vue 深层响应式代理，避免代理对象身份与引擎生命周期互相干扰。

这与 Vue 包装编辑器或地图组件的方式类似：组件负责输入输出，实例负责内部高频工作。Cesium 实例在卸载时解除事件、计时器、ResizeObserver，再销毁 Viewer。切换后端时，加载版本号阻止旧请求覆盖新场景。

曾遇到模板 `someValue ?? []` 每次渲染生成新数组，触发 watch → 样式更新 → 指标更新 → 再渲染。当前用稳定的空数组与 computed，渲染类再按集合内容判定变化。理解“引用变化”和“业务值变化”的区别，对你已有的 Vue 技能很有用。

## 2. 一个业务对象不等于一个 mesh

`data/model.json` 的每个业务构件有 `geometry_ids`。树选择先获得业务 ID，再展开到所有几何片段；画布拾取读取 feature 的 `componentId`，反查所属业务对象。`lib/modelState.ts` 中的树压缩、分组收集、合并 bounds 都是纯函数，适合先读和运行测试。

树上一个管线分组没有独立 mesh，选择分组时要收集全部后代业务对象并合并包围盒。定位采用与 tileset 相同的坐标变换，不用未经转换的 CSV 坐标直接驱动相机。

附件没有地理定位，工程显示采用一个固定 ENU 参考框架。这只为引擎提供稳定坐标，不表示动力站真的位于经纬度零点。源 tileset 的轴字符串为小写 z，而引擎枚举区分大小写，因此显式设置 `modelUpAxis: Axis.Z`。

## 3. 日期决定状态，状态决定颜色

数据库中 `welded_on` 非空表示焊口已完成。后端用管线号与焊口号定位记录，再将焊口、两端材料映射成 `completed_geometry_ids`。内部空白先归一化；`-` 占位端点不猜测，报告缺失关系。

前端颜色规则：选中黄色优先，其次完成绿色，否则恢复原材质。不同焊口可能共用一个相邻材料，所以清空一个焊口后，应重新计算整个完成集合，不能直接把该焊口的三个对象全部取消颜色。当前由后端按数据库现状重算，前端使用返回集合。

Cesium 的默认颜色混合会把状态色与原材质相乘，原本红色的几何可能无法清楚显示黄色。实现显式使用 REPLACE，默认白色 feature 仍保留源材质。附件部分焊口很薄，嵌在法兰内，仅修改表面颜色仍会被遮挡；当前额外绘制所选对象真实 bounds 的黄色轮廓，并通过 depthFailMaterial 让轮廓在遮挡处可见。这是一种定位提示，不新增或改变原构件几何。

浏览器测试检查实际画布区域的黄色选择轮廓和绿色进度像素，避开工具栏与引擎标识，并结合稳定 ID 与截图复核。黄色轮廓证明所选对象的位置提示已显示，不将瓦片中的 feature 计数当成该 feature 逐像素可见的证明。

## 4. 瓦片不是一次加载后永远不变

LOD 切换会生成新的 feature 对象，旧 feature 引用不能代表新瓦片。当前 `tileVisible` 首次看到内容时缓存稳定 ID 与原始颜色；业务状态修改只增加 revision，新瓦片出现时按最新 revision 重放。`tileUnload` 删除缓存，销毁场景时一并清理。

用于样式重放的缓存与当前可见瓦片是两个集合。性能面板只计最后渲染帧中的瓦片特征，不把已移出视角或旧 LOD 的缓存当成可见内容。瓦片内的 feature 数仍不等于逐像素可见数，因此画面验收同时看截图。

## 5. 20 FPS 应测实际帧

附件最精细层约 106 万三角面，交互期间提高屏幕空间误差、优先采用粗层，实际层级仍取决于观察距离；停止约 450ms 后恢复细节阈值。空闲采用按需渲染，不能用静止时两次绘制间隔计算“掉帧”。采样在 Cesium 的 postRender 事件中进行，只记录交互期间实际发生的帧，输出平均 FPS 与 P95 帧间隔。

Playwright 在浏览器内连续发出旋转、平移、缩放输入，避免每次输入都通过自动化 RPC 和 trace 截图强制 GPU 读回而污染测量。测试仍包含完整硬件、分辨率和阈值，不代表所有电脑都能达到同一帧率。强制软件渲染时本机就无法达到题目要求。

## 6. 从这里转到 Python

先看 `backend-node/src/app.ts` 与 `backend-python/app/main.py` 的同名接口，再看两版 db/data 模块与 progress 计算。它们的外部契约相同：前端只切换 API 前缀，无需知道语言。Python 普通 `def` + 同步 psycopg 路由在线程池执行，适合先掌握类型、校验、SQL 事务和 with 资源管理，再学习 async。

建议先跑 `learning/01_node.mjs` 与 `learning/01_python.py`，再用 `learning/02_call_api.py` 调本地真实接口。语法和异步差异见《Python对照Node学习.md》；不要把 Node 的 async 调用行为逐字套到 Python coroutine。
